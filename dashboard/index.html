چرا هر انتخاب؟
تصمیم ۱
SQLite به جای PostgreSQL یا MongoDB

سیمرغ باید کاملاً آفلاین باشد. SQLite روی همه دستگاه‌ها اجرا می‌شود، نیاز به سرور ندارد، و با FTS5 جستجوی معنایی فارسی را پشتیبانی می‌کند. سرعت کافی برای استفاده شخصی دارد.

تصمیم ۲
دو مدل به جای یک — Qwen2.5 + Gemma3

سرعت و عمق هر دو مهم‌اند. Qwen2.5 برای پاسخ‌های سریع و روزمره. Gemma3 برای استدلال فلسفی و چندلایه. سیمرغ بر اساس پیچیدگی پرسش انتخاب می‌کند کدام را فراخوانی کند.

تصمیم ۳
Python به جای Rust یا Go برای backend

سرعت توسعه مهم‌تر از سرعت اجرا است در این مرحله. Python اکوسیستم ML کامل دارد. بعداً اگر bottleneck پیدا شد، ماژول‌های حیاتی به Rust ترجمه می‌شوند.

تصمیم ۴
NetworkX برای Knowledge Graph — نه Neo4j

Neo4j نیاز به سرور جداگانه دارد. NetworkX در حافظه کار می‌کند و روی SQLite persist می‌شود. برای حجم اولیه (هزاران node) کافی است. در فاز ۳ اگر graph بزرگ شد، مهاجرت امکان‌پذیر است.

تصمیم ۵
منشور را در Python hardcode کن، نه در prompt

اگر منشور فقط در system prompt باشد، مدل می‌تواند آن را نادیده بگیرد. بهتر است منشور در کد Python به صورت structural constraint پیاده‌سازی شود — مثل middleware که هر پاسخ از آن عبور می‌کند.

تصمیم ۶
فاز ۱ فقط برای مهدی — بدون عجله برای انتشار

بزرگ‌ترین اشتباه در پروژه‌های AI این است که زود منتشر کنی و بازخورد منفی شکل درست فکر کردن را تخریب کند. سیمرغ اول باید برای خودت واقعاً مفید باشد. سپس دیگران.
