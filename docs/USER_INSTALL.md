# نصب و اجرای کاربر عادی

این مسیر برای کسی است که هیچ شناختی از Python، FastAPI، llama.cpp یا ساختار داخلی سیمرغ ندارد.

## اجرای محلی روی Linux

در ریشهٔ مخزن فقط این فایل را اجرا کنید:

```bash
./install.sh
```

اسکریپت به‌صورت پیش‌فرض در سطح کاربر اجرا می‌شود و برای نصب معمولی به root نیاز ندارد. در اولین اجرای تعاملی، محل داده‌های شخصی و مدل‌ها را می‌پرسد. مسیر پیش‌فرض:

```text
~/.local/share/simorgh
```

اطلاعات تنظیمات محلی در:

```text
~/.config/simorgh/runtime.json
~/.config/simorgh/runtime.env
```

ذخیره می‌شود.

## چیزی که بعد از نصب اتفاق می‌افتد

سیمرغ یک محیط Python جداگانه برای خودش می‌سازد، وابستگی‌های runtime را نصب می‌کند، پورت آزاد محلی را انتخاب می‌کند، سرویس را روی loopback بالا می‌آورد و مرورگر را به رابط محلی باز می‌کند.

هیچ حساب ابری، API key یا telemetry اجباری وجود ندارد.

## بدون مدل هم کار می‌کند

مدل زبانی شرط اجرای هسته نیست. در نبود مدل، مسیر گفت‌وگو به بازیابی مستقیم از پایگاه‌های دانش محلی برمی‌گردد و پاسخ را با provenance روشن نشان می‌دهد.

بنابراین پیام «مدل نصب کن تا برنامه کار کند» مسیر پیش‌فرض نیست.

## نصب مدل محلی

رابط کاربر سخت‌افزار را بررسی می‌کند و مدل‌های موجود در catalog را به‌صورت conservative دسته‌بندی می‌کند. دانلود مدل خودکار نیست.

با انتخاب یک مدل:

1. سازگاری RAM / فضای دیسک بررسی می‌شود.
2. SHA-256 مورد انتظار از catalog ثبت‌شده استفاده می‌شود.
3. فایل در مسیر مدل کاربر و با فایل provenance جانبی ذخیره می‌شود.
4. backend محلی llama.cpp پیدا یا از release رسمی آن دریافت می‌شود.
5. hash فایل backend بررسی می‌شود.
6. `llama-server` فقط روی `127.0.0.1` اجرا می‌شود.
7. endpoint واقعی در تنظیمات runtime ذخیره می‌شود.

مدل واردشده از مسیر محلی نیز با SHA-256 ثبت می‌شود.

## کنترل فایل‌ها و داده‌ها

کد مخزن و داده‌های کاربر از هم جدا نگه داشته می‌شوند. تغییر یا حذف حافظهٔ کاربر نباید با به‌روزرسانی کد باعث از دست رفتن داده شود.

مدل‌ها در `models/` داخل runtime کاربر قرار می‌گیرند و پوشه‌های import، transcript، audio و proposal نیز جدا هستند.

## حالت آفلاین

پس از نصب dependencyها و دریافت داده‌های لازم، اجرای هسته روی loopback می‌تواند بدون سرویس ابری انجام شود. دریافت مدل یا backend طبیعتاً به شبکه نیاز دارد و فقط با اقدام کاربر انجام می‌شود.

## مسیر توسعه‌دهنده

مسیر توسعه همچنان می‌تواند مستقیم از Python و تست‌های repository استفاده کند. این مسیر با launcher کاربر عادی یکی نیست و نباید dependencyهای توسعه را به کاربر عادی تحمیل کند.

## وضعیت فعلی بسته‌بندی

`install.sh` launcher کاربرمحور است. یک بستهٔ کاملاً self-contained مثل AppImage یا installer native مرحلهٔ بعدی انتشار محصول است و از مسیر توسعهٔ فعلی جدا نگه داشته می‌شود.
