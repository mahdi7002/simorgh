# نصب و اجرای کاربر عادی

این مسیر برای کسی است که هیچ شناختی از Python، FastAPI، llama.cpp یا ساختار داخلی سیمرغ ندارد.

## مسیر بدون محیط توسعه: AppImage

برای x86_64 Linux، مسیر اصلی و self-contained استفاده این است:

```bash
chmod +x SIMORGH-x86_64.AppImage
./SIMORGH-x86_64.AppImage
```

در این حالت Python، dependencyهای اصلی runtime، رابط وب و پایگاه دانش canonical داخل بسته هستند. روی سیستم کاربر نیازی به Git، pip یا Python نیست.

AppImage در حالت عادی هیچ دادهٔ شخصی را داخل خود بسته نمی‌نویسد. حافظه، تنظیمات، importها، transcriptها، logها و مدل‌های دانلودشده در مسیرهای کاربر نگهداری می‌شوند.

در اولین اجرا، در صورت وجود `zenity` یا `kdialog` محل داده و مدل‌ها انتخاب می‌شود؛ در غیر این صورت مسیر پیش‌فرض:

```text
~/.local/share/simorgh
```

استفاده می‌شود.

راهنمای کامل AppImage: [`APPIMAGE.md`](APPIMAGE.md)

## مسیر توسعه یا fallback

در ریشهٔ مخزن می‌توان مسیر user-first مبتنی بر launcher را نیز اجرا کرد:

```bash
./install.sh
```

این launcher در سطح کاربر اجرا می‌شود و برای نصب معمولی به root نیاز ندارد. در صورت اجرای تعاملی، محل داده‌های شخصی و مدل‌ها را می‌پرسد.

## چیزی که بعد از شروع اتفاق می‌افتد

سیمرغ سرویس محلی را فقط روی loopback بالا می‌آورد و رابط وب را در مرورگر باز می‌کند. پورت محلی در صورت اشغال بودن به‌صورت خودکار انتخاب می‌شود.

هیچ حساب ابری، API key یا telemetry اجباری وجود ندارد.

## بدون مدل هم کار می‌کند

مدل زبانی شرط اجرای هسته نیست. در نبود مدل، مسیر گفت‌وگو به بازیابی مستقیم از پایگاه‌های دانش محلی برمی‌گردد و پاسخ را با provenance روشن نشان می‌دهد.

بنابراین پیام «مدل نصب کن تا برنامه کار کند» مسیر پیش‌فرض نیست.

## نصب مدل محلی

رابط کاربر سخت‌افزار را بررسی می‌کند و مدل‌های موجود در catalog را به‌صورت conservative دسته‌بندی می‌کند. دانلود مدل خودکار نیست.

با انتخاب یک مدل:

1. سازگاری RAM و فضای دیسک بررسی می‌شود.
2. SHA-256 مورد انتظار از catalog ثبت‌شده کنترل می‌شود.
3. فایل در مسیر مدل کاربر و با metadata جانبی ثبت می‌شود.
4. provenance قابل اعتماد فقط وقتی اعلام می‌شود که منبع/هش مورد انتظار با مدل catalog منطبق باشد.
5. backend محلی llama.cpp پیدا یا از release رسمی آن دریافت می‌شود.
6. hash فایل backend بررسی می‌شود.
7. `llama-server` فقط روی `127.0.0.1` اجرا می‌شود.
8. endpoint واقعی در تنظیمات runtime ذخیره می‌شود.

مدل واردشده از مسیر محلی نیز SHA-256 می‌شود، ولی hash کردن به‌تنهایی آن را به یک منبع trusted تبدیل نمی‌کند.

## کنترل فایل‌ها و داده‌ها

کد برنامه و داده‌های کاربر از هم جدا نگه داشته می‌شوند. به‌روزرسانی AppImage نباید حافظه یا مدل‌های کاربر را حذف کند.

## حالت آفلاین

بعد از داشتن AppImage، اجرای هسته و پایگاه دانش می‌تواند بدون سرویس ابری ادامه یابد. دانلود مدل یا backend طبیعتاً به شبکه نیاز دارد و فقط با اقدام صریح کاربر انجام می‌شود.

## وضعیت انتشار

بستهٔ self-contained برای x86_64 Linux از طریق workflow رسمی repository ساخته می‌شود. نسخه‌های tag شده با الگوی `v*` می‌توانند به‌صورت release GitHub منتشر شوند.

AppImage یک بستهٔ architecture-specific است. build فعلی x86_64 است و بستهٔ ARM64 هنوز جداگانه ساخته نمی‌شود.

## اجرای دائمی پس‌زمینه

در نصب معمولی با `./install.sh`، اگر systemd کاربر در دسترس باشد، سیمرغ به‌صورت یک سرویس کاربری نصب و فعال می‌شود:

- `Restart=always` برای بازگشت خودکار سرویس پس از crash یا توقف ناخواسته
- اجرای خودکار با user manager سیستم
- فعال‌سازی linger برای ادامهٔ سرویس پس از خروج از نشست کاربر، در صورت پشتیبانی سیستم
- اجرای هسته فقط روی `127.0.0.1`
- داده و لاگ خارج از مخزن و در runtime کاربر

وضعیت سرویس:

```bash
systemctl --user status simorgh.service
journalctl --user -u simorgh.service -n 80 --no-pager
```

شروع دوباره:

```bash
systemctl --user restart simorgh.service
```

توقف موقت:

```bash
./stop.sh
```

پس از توقف، برای فعال‌سازی دوباره نصب‌کننده را اجرا کنید یا از `systemctl --user start simorgh.service` استفاده کنید.

نصب‌کننده در نبود systemd کاربر، به launcher فعلی fallback می‌کند.
