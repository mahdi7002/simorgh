# معماری عامل‌محور و چشم‌انداز ۳۰ ساله‌ی سیمرغ

## بخش ۱: وضعیت واقعی معماری عامل‌محور

### وضعیت فعلی هسته

مسیر زندهٔ فعلی دیگر مجموعه‌ای از پرسوناهای کاملاً مستقل نیست. کنترل‌پلین سبک سیمرغ اکنون این زنجیره را اجرا می‌کند:

`Question → Dispatcher → Tool Planner → Tools → Blackboard → Personas → Reviewer → Response`

اجزای اصلی در `core/orchestration/` قرار دارند:

1. **Dispatcher**: مسیریابی قطعی و کم‌هزینه با سقف پیش‌فرض دو پرسونا برای سخت‌افزار ضعیف.
2. **Blackboard**: وضعیت مشترک درخواست، خروجی پرسوناها و metadata تولید.
3. **Tool Planner / Registry**: فراخوانی ابزارهای محلی با provenance؛ خروجی ابزار صرفاً evidence است، نه حقیقت خودکار.
4. **Reviewer**: دروازهٔ قطعی برای پرسش‌های evidence-sensitive؛ نبود evidence یا ناسازگاری نقل را به‌عنوان هشدار ثبت می‌کند.
5. **Governance Runtime**: قراردادهای provider-neutral و Human Gate برای mutation و self-improvement.

### آنچه هنوز عمداً پیاده‌سازی نشده است

این موارد نباید با قابلیت‌های فعلی قاطی شوند:

- **Semantic/LLM Dispatcher**: هنوز dispatcher پیش‌فرض rule-based است.
- **حلقهٔ چندمرحله‌ای ابزار و بازبینی**: مسیر فعلی یک اجرای bounded دارد؛ حلقهٔ کامل observe → re-plan → execute هنوز هستهٔ اصلی نیست.
- **MCP و external provider adapters**: هنوز قابلیت اختیاری و جدا از authority سیمرغ‌اند.
- **اجرای خودکار تغییرات کد یا policy**: همچنان ممنوع و Human-Gated است.

### اصل سخت‌افزاری

مدل زبانی یک جزء قابل‌تعویض است، نه هویت سیستم. روی ماشین‌های کم‌منبع، تعداد فراخوانی‌های هم‌زمان باید bounded بماند و timeout باید با latency واقعی CPU سازگار باشد.

برای همین، کیفیت مدل و معماری باید جداگانه اندازه‌گیری شوند:

`Backend works ≠ Model is accurate`

و:

`AI-generated ≠ Verified`

این تفکیک بخشی از قرارداد provenance سیمرغ است، نه یک ویژگی تزئینی.

### الگوی اجرایی فعلی

State machine سبک موجود در `core/orchestration/` و `core/orchestration/runtime.py` پایهٔ مناسب توسعهٔ بعدی است؛ اما هر قابلیت جدید باید پیش از درج در ماتریس README، هم implementation، هم regression test و هم CI coverage داشته باشد.

## بخش ۲: چشم‌انداز ۳۰ ساله

### پیش‌بینی صنعت
مدیران‌عامل OpenAI، Google DeepMind و Anthropic هر سه AGI را ظرف ۵ سال آینده پیش‌بینی کرده‌اند.
معادل «۱۰۰ سال پیشرفت در ۵ تا ۱۰ سال» (تحلیل داریو آمودی، مدیرعامل Anthropic).

### نتیجه برای سیمرغ
مدل زیرین (llama-server، qwen2.5) یک کالای موقتی است، نه دارایی اصلی.

**دارایی‌های ماندگار که باید همین حالا محکم‌شان کرد:**

1. کورپوس فرهنگی/دینی با provenance (quran.db، شاهنامه، متون کلاسیک)
2. معماری پرسوناها به‌عنوان لایه‌ای مستقل از مدل — قابل تعویض بدون بازنویسی
3. حاکمیت داده و آفلاین‌بودن — روند جهانی «Sovereign AI» (۷۱٪ مدیران جهانی آن را ضرورت راهبردی می‌دانند)
4. لایه‌ی راستی‌آزمایی/ضد توهم — از «مزیت» به «الزام» تبدیل می‌شود

### اصل طراحی
مدل = plug-in قابل تعویض. دیتا + پرسونا + حکمت + قوانین راستی‌آزمایی = هسته‌ی ثابت و رشدپذیر.
