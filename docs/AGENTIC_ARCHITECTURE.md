# معماری عامل‌محور و چشم‌انداز ۳۰ ساله‌ی سیمرغ

## بخش ۱: از پرسونای پاسخ‌دهنده به تیم اجراکننده

### مشکل فعلی
هر پرسونا مستقل و بدون حافظه‌ی مشترک پاسخ می‌دهد؛ هیچ ابزار واقعی صدا نمی‌زند؛ هیچ مرحله‌ی بازبینی وجود ندارد.

### تغییرات لازم (۴ لایه، بدون فریمورک سنگین)

1. **لایه‌ی مدیر/دیسپچر** — یک مدل سبک (qwen2.5-1.5b فعلی کافیست) درخواست کاربر را می‌گیرد و
   تشخیص می‌دهد کدام پرسونا(ها) لازم‌اند. نباید بیش از ۲-۳ پرسونا هم‌زمان روی این سخت‌افزار فراخوانی شوند.

2. **حافظه‌ی مشترک (blackboard)** — یک state مشترک بین پرسوناها؛ نتیجه‌ی کار یک پرسونا در دسترس بعدی باشد.

3. **ابزار واقعی برای هر پرسونا** — نه فقط تولید متن: خلیق → book_chunks_fts، حافظ → quran.db،
   راصد → وضعیت سنسور ESP32. حلقه‌ی واقعی: درک → برنامه‌ریزی → فراخوانی ابزار → مشاهده‌ی نتیجه → تکرار.

4. **نقش ناظر/بازبین کیفیت** — قبل از پاسخ نهایی، یک پرسونای «ناظر» ادعاهای قرآنی/شعری را با
   دیتابیس تطبیق دهد (ضد توهم). سقف تکرار (۳-۵ دور) برای جلوگیری از حلقه‌ی بی‌نهایت الزامی است.

### الگوی پیاده‌سازی
State machine ساده در FastAPI فعلی: `dispatch() → execute() → review() → respond()`.
بدون AutoGen/CrewAI — سازگار با فلسفه‌ی ضد اورانجینیرینگ پروژه.

## بخش ۲: چشم‌انداز ۳۰ ساله

### پیش‌بینی صنعت
مدیران‌عامل OpenAI، Google DeepMind و Anthropic هر سه AGI را ظرف ۵ سال آینده پیش‌بینی کرده‌اند.
معادل «۱۰۰ سال پیشرفت در ۵ تا ۱۰ سال» (تحلیل داریو آمودی، مدیرعامل Anthropic).

### نتیجه برای سیمرغ
مدل زیرین (llama-server، qwen2.5) یک کالای موقتی است، نه دارایی اصلی.

**دارایی‌های ماندگار که باید همین حالا محکم‌شان کرد:**

1. کورپوس فرهنگی/دینی با provenance (quran.db، شاهنامه، متون کلاسیک)
2. معماری پرسوناها به‌عنوان لایه‌ای مستقل از مدل — قابل تعویض بدون بازنویسی
3. حاکمیت داده و آفلاین‌بودن — روند جهانی «Sovereign AI» (۷۱٪ مدیران جهانی آن را ضرورت راهبردی می‌دانند)
4. لایه‌ی راستی‌آزمایی/ضد توهم — از «مزیت» به «الزام» تبدیل می‌شود

### اصل طراحی
مدل = plug-in قابل تعویض. دیتا + پرسونا + حکمت + قوانین راستی‌آزمایی = هسته‌ی ثابت و رشدپذیر.
